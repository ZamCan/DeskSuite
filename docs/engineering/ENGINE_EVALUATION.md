# Engine decisions and remaining evaluations

This is a current summary of research begun on 2026-10-27; it is not a release or device-validation claim. See the [engine register](ENGINE_INTEGRATION_REGISTER.md), [current status](CURRENT_STATUS.md) and [validation](VALIDATION.md).

- **OCR:** Tesseract4Android 4.9.0 / Tesseract 5.5.1 and bundled English/Kiswahili models are integrated in source. Recognition quality, native lifecycle, licensing closure and low-memory performance still need physical-device checks. Google ML Kit and other OCR/model alternatives were not adopted as replacements; runtime downloads or telemetry would conflict with the local-first requirements unless separately reviewed and authorized.
- **Existing PDF:** `dart_pdf_editor` and `pdf_document` 10.0.0 are integrated for viewing/editing, bounded inspection and combining. The `pdf` writer creates new documents; it alone is not an existing-PDF editor. Android `PdfRenderer` and PDFium remain alternatives requiring native lifecycle, ABI, security and feature review. Current PDF limits and tests are in [PDF support](PDF_SUPPORT.md).
- **Office:** bounded Dart content reading/writing is integrated, with explicit loss of layout and complex objects. OpenDocument.core 7.6.1 C++/WASM is a separately bundled, disabled-by-default Android read-only preview; it is not conversion/editing and needs isolation, fidelity, memory, accessibility and licence review. LibreOffice has Android integration approaches but is not bundled or configured, and an external `soffice` adapter is not implemented. See [Office support](OFFICE_SUPPORT.md).
- **Image and print:** use the shared bounded image processor, PDF writer and physical media catalogue rather than the duplicate engines on older branches. Actual codec behavior, print devices and large-image memory remain validation gates.
- **Optional SLM:** no language model is integrated. Any future local suggestion engine must be optional, private, licensed, user-controlled and reviewable; it must not silently replace OCR or become required for essential workflows. See the protocol in the engine register.

A package, successful fake-adapter check, filename extension or partial renderer is not proof of faithful output. Test representative and hostile real files, retain originals, verify outputs independently, and document the exact distribution dependency/notice closure before claiming compatibility.
