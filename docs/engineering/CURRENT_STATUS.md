## Creative editor engineering increment — 2026-11-06 (vertical alignment)

- Added `DesignController.alignVertical` (top, middle, bottom of the page) beside the existing horizontal alignment, and three matching buttons in the object inspector's "Align on page" row. The change edits the real object position, is part of undo/redo and is saved in `.dsdesign`; the project format version is unchanged.
- Page alignment is now a no-op when the object is already at the requested position, so repeated alignment no longer adds empty undo entries (this also applies to the existing horizontal actions).
- Alignment uses the object's unrotated bounding box; rotated objects are not aligned by their visual extent.
- Tests added: two controller tests in `test/design_engine_test.dart` (page-relative geometry, undo/redo, persistence, no empty history) and one inspector widget test in `test/design_editor_widgets_test.dart`.
- **Verification state: not verified.** The environment that produced this change had no Flutter or Dart toolchain, so `dart format`, `flutter analyze` and `flutter test` were not run, and no build or device check was performed. Treat the change and its tests as unverified until CI or a local run passes.

## Creative editor engineering increment — 2026-11-03

- Updated the existing Creative Studio object model with a backward-compatible `visible` property. Existing version-1 projects without this field decode as visible; the project format version remains unchanged.
- Added a working visibility toggle to the object inspector. Hidden objects are omitted from canvas rendering and raster/PDF output, excluded from canvas hit testing, and their decoded image resources are released from the editor cache until shown again.
- Added editable opacity presets (25%, 50%, 75%, 100%) in the object inspector. The existing renderer applies opacity to text, vector shapes and image layers; edits remain part of the saved project and undo/redo history.
- Added a backward-compatible canvas-movement lock. Locked layers remain selectable and editable through deliberate inspector actions but cannot be dragged or resized on the canvas; blocked gestures do not create empty undo entries.
- Hardened the shared object update path so every object edit is checked against the project byte limit, rather than checking only text changes.
- Added unit coverage for visibility/lock serialization, old-project compatibility, hit testing, protected movement, undo/redo and opacity round-tripping, plus a widget test for the actual inspector controls.
- Source changes are committed directly to `main`; the current implementation checkpoint is `6c31a2b9d9ac892067ad3f76a281968b07907240`. GitHub Actions run [41667608392](https://github.com/ZamCan/DeskSuite/actions/runs/41667608392) was queued at the time of this status update. Do not treat the new tests, analyzer, APK build or device behaviour as verified until that run completes and real-device checks are performed.
- This is a focused editor foundation increment, not delivery of the full raster, vector or motion-graphics roadmap. No APK was built, signed or installed during this remote source update.

## Owner's local validation and signing

Use the **existing** Flutter/Dart and Android toolchains on the owner's machine. Do not download Android toolchains or create a new key to update an existing installation. After safely importing this source, run the commands in [validation](VALIDATION.md), especially `flutter analyze --no-pub` and the full `flutter test --no-pub` suite. Resolve failures before promotion. Inspect Office output in independent applications; test PDF open/save/combine/split, OCR, scanner, photo, accessibility, file providers and printing on real devices.

Keep application ID `com.zamcan.desksuite` and the existing private signing identity. Back up private data and export important documents before any update. Build and verify a signed APK/AAB locally with the existing key only after tests pass. No signed installation or release readiness is claimed here.
