# Conversion registry and support boundaries

The in-app **Conversion routes** catalogue (`lib/workspace/conversion_catalog.dart`) opens the real studio for each available route. A route being listed does not mean native Android file pickers have been device-tested. All operations are local and do not require an account. Each export asks for a user-selected destination; choose a **different** name/location because an external provider can permit an explicit overwrite.

| PNG/JPEG/WebP → PNG or JPEG | `image` 4.12; Photo Studio, `lib/images/photo_processor.dart` | First frame only; image is re-encoded. JPEG quality is adjustable and transparency becomes white. Input ≤8 MiB, 12 MP, 8192 px per side; working output ≤16 MiB. Metadata is not guaranteed to survive. Compare actual encoded bytes before saving; size reduction is not guaranteed. | Signature and encoded header dimensions checked before save; host tests fully decode generated PNG/JPEG and assert dimensions: `test/photo_processor_test.dart`, `test/photo_widget_test.dart`. Native destination/provider behavior unverified. |
| PNG/JPEG/WebP → multipage image PDF | `image`, `pdf` 3.13.1; Scan & assemble, `lib/document_scan/` | User images are normalized to PNG. Manual projective corner correction, rotation and fixed grayscale/B&W are optional. Up to 8 pages, 24 MP and 32 MiB processed images; A4 or US Letter, 10 mm margins, orientation auto-selected. Image-only, no OCR/text layer. PDF does not preserve source metadata. | Bounded decode, PDF header/end check; host tests `scan_processor_test.dart`, `scan_pdf_test.dart`, `scan_studio_widget_test.dart`, `sample_assets_test.dart`. | `.dsdesign` → PNG or one-page image PDF | DeskSuite canvas, `image`/`pdf`; Creative Studio | Flattened raster result, not editable or selectable text. ## Explicitly unavailable

- Scanner page reordering applies to its own image draft. Existing PDFs are opened separately in PDF Studio using the pinned `dart_pdf_editor` engine; supported page and annotation operations are saved as a separate copy. Real-world PDF compatibility, complex/protected documents, performance and native file-provider behavior still require validation.
- DOCX/XLSX/PPTX **layout-faithful** conversion. The built-in engine preserves
  content, not layout; pixel-accurate rendering requires an installed LibreOffice.
- Writing DOCX/XLSX/PPTX from the converter (only ODT/ODS/PDF/TXT/CSV are written).
- PDF-to-Office conversion, macros, form fields and digital signatures.
- Structural PDF optimization, target-file-size guarantees, batch conversion and cloud conversions.
- Image percentage, DPI/physical-size resampling, advanced compression presets or metadata controls.

Unsupported routes have no action in the catalogue. No file is converted by merely renaming an extension. Processing runs in background isolates in the app, but progress is an indeterminate busy state; cancellation of a running transform and full memory profiling are not implemented. Input bounds reduce risk but do not guarantee processing on every device. See [engine evaluation](engineering/ENGINE_EVALUATION.md), [user guide](USER_GUIDE.md) and [file formats](FILE_FORMATS.md).
