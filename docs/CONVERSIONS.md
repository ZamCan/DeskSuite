# Conversion registry and support boundaries

The in-app **Conversion routes** catalogue (`lib/workspace/conversion_catalog.dart`) opens the real studio for each available route. A route being listed does not mean native Android file pickers have been device-tested. All operations are local and do not require an account. Each export asks for a user-selected destination; choose a **different** name/location because an external provider can permit an explicit overwrite.

## Explicitly unavailable

- Existing PDF → image, merge, split, reorder, edit, read or compressed PDF.
- Existing PDF → image, merge, split, reorder, edit, read or compressed PDF. The scanner reorders **its own image pages**, not imported PDF pages.
- DOCX/XLSX/PPTX **layout-faithful** conversion. The built-in engine preserves
  content, not layout; pixel-accurate rendering requires an installed LibreOffice.
- Layout-faithful DOCX/XLSX/PPTX conversion. The converter writes content-level outputs; the separate content editor can create DOCX/XLSX/ODT/ODS/PDF/TXT/CSV copies but does not preserve full layout.
- PDF-to-Office conversion, macros, form fields and digital signatures.
- Structural PDF optimization, target-file-size guarantees, batch conversion and cloud conversions.
- Image percentage, DPI/physical-size resampling, advanced compression presets or metadata controls.

Unsupported routes have no action in the catalogue. No file is converted by merely renaming an extension. Processing runs in background isolates in the app, but progress is an indeterminate busy state; cancellation of a running transform and full memory profiling are not implemented. Input bounds reduce risk but do not guarantee processing on every device. See [engine evaluation](engineering/ENGINE_EVALUATION.md), [user guide](USER_GUIDE.md) and [file formats](FILE_FORMATS.md).
