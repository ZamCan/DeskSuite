# Conversion registry and support boundaries

The in-app **Conversion routes** catalogue (`lib/workspace/conversion_catalog.dart`) opens the real studio for each available route. A route being listed does not mean native Android file pickers have been device-tested. All operations are local and do not require an account. Each export asks for a user-selected destination; choose a **different** name/location because an external provider can permit an explicit overwrite.

## Explicitly unavailable

- Existing PDF → a single merged PDF from different files, batch images or a target-size compressed PDF.
- DOCX/XLSX/PPTX **layout-faithful** conversion. The built-in converter and editor preserve selected content, not full layout. The opt-in experimental renderer is a read-only preview, not conversion, and is not device-validated.
- PDF-to-Office conversion, Office macros and cryptographic digital signatures. PDF & Documents can fill supported existing form fields; this is not form creation.
- Structural PDF optimization, target-file-size guarantees, batch conversion and cloud conversions.
- Comprehensive image metadata controls and guarantees of a chosen compressed file size. Percentage resizing and bounded JPEG optimization are available; physical-size/DPI inputs calculate pixel dimensions but do not guarantee print calibration or embed DPI metadata.

Unsupported routes have no action in the catalogue. No file is converted by merely renaming an extension. Some image operations run in background isolates; PDF inspection can run on the UI isolate. Progress and cancellation vary by workflow, and full memory profiling is not implemented. Input bounds reduce risk but do not guarantee processing on every device.
